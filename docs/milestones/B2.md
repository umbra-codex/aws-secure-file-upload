## Goal

Put Lambda 1 on the internet, safely. You build:

- **An HTTP API** (API Gateway) with one route, `POST /upload-url`, that runs Lambda 1. This is the team's only API: in A4, the status route attaches to it too.
- **Access logs**: one JSON line per request, kept 14 days, so every call can be traced.
- **The size limit on the upload itself.** B1's handler already refuses a request that *says* the file is too big. Here you make S3 refuse a file that *is* too big, whatever the client claimed.

When this merges, A4 can start: it needs your `api_id` and `api_execution_arn` outputs. Read A1's [How to read the blocks](A1.md#how-to-read-the-blocks) if you haven't.

## Part 1: The size condition (`modules/upload_api/src/handler.py`)

#### 1. Add a condition to the presigned POST

In the `generate_presigned_post` call from B1, add one argument:

| Argument | Set To |
|---|---|
| `Conditions` | a list holding one condition: `["content-length-range", 1, <the limit in bytes>]`, where the limit is the same `MAX_SIZE_MB` × 1024 × 1024 your handler already checks against |

Nothing else in the handler changes.

**The size is checked twice.** The handler's check reads the `size` the client *declared*, and a client can lie. A presigned POST carries a signed **policy**: a list of conditions S3 checks against the real upload. `content-length-range` makes S3 itself reject any file outside 1 byte to the limit, before it stores anything. The key condition from B1 is already in that policy (boto3 added it), so don't add a second one. The content type is different: the policy doesn't lock it, so the declared type is only a first filter. D checks each file's real type from its first bytes.

**Tags:** not applicable (this is code, not a Terraform block).

**Docs:** [boto3 generate_presigned_post](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/s3/client/generate_presigned_post.html) · [POST policy conditions (S3)](https://docs.aws.amazon.com/AmazonS3/latest/API/sigv4-HTTPPOSTConstructPolicy.html)

**✅ Checkpoint: step 1 (handler)**
Save `src/handler.py`, then run the check in your terminal before you commit. No AWS needed; [A1](A1.md#how-to-see-your-results) explains the output:

```

Step 1 should now be ✅. It confirms the handler passes `Conditions=` with `["content-length-range", 1, <limit>]`, where the limit is a name or expression (the same bytes value the handler checks), not a number typed in. ## Part 2: The API and its stage (`modules/upload_api/api.tf`, new file)

An **HTTP API** is API Gateway's simpler, cheaper kind of API. Three pieces make it answer requests: the API itself, a **stage** (a deployed version of it, with its own URL and settings), and **routes** that send requests somewhere. You build the first two here, and the route in Part 3.

#### 2. The access log group

**Block Type:** `resource`
**Resource Type:** `aws_cloudwatch_log_group`
**Resource Name:** `api_access`

| Argument | Set To |
|---|---|
| `name` | `/aws/apigateway/` followed by the `project_name` variable followed by `-api` |
| `retention_in_days` | `14` |
| `tags` | `Name` = the same expression you wrote for `name`, repeated; `Role` = `"api"`; `ManagedBy` = `"terraform"` |

**Tags:** yes, through the `tags` argument above.

**Docs:** [aws_cloudwatch_log_group](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/cloudwatch_log_group)

This is a second log group, separate from Lambda 1's. Lambda 1's group shows what your code did; this one shows every request that reached the API, including ones that never got to your code.

#### 3. The API

**Block Type:** `resource`
**Resource Type:** `aws_apigatewayv2_api`
**Resource Name:** `this`

| Argument | Set To |
|---|---|
| `name` | the `project_name` variable followed by `-api` |
| `protocol_type` | `"HTTP"` |
| `tags` | `Name` = the same expression you wrote for `name`, repeated; `Role` = `"api"`; `ManagedBy` = `"terraform"` |

**Tags:** yes, through the `tags` argument above.

**Docs:** [aws_apigatewayv2_api](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/apigatewayv2_api) · [HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html)

`apigatewayv2` is the Terraform name for HTTP APIs (and WebSocket APIs). The older REST API uses `aws_api_gateway_*` resources; don't mix the two. `this` is the usual resource name when a module has only one of something.

#### 4. The stage

**Block Type:** `resource`
**Resource Type:** `aws_apigatewayv2_stage`
**Resource Name:** `default`

| Argument | Set To |
|---|---|
| `api_id` | the `id` of `aws_apigatewayv2_api.this` |
| `name` | `"$default"` |
| `auto_deploy` | `true` |
| `access_log_settings` (nested block) | one block with the two rows below |
| `access_log_settings` → `destination_arn` | the `arn` of `aws_cloudwatch_log_group.api_access` |
| `access_log_settings` → `format` | a JSON object built with `jsonencode`, with these keys and values: `requestId` = `"$context.requestId"`, `ip` = `"$context.identity.sourceIp"`, `requestTime` = `"$context.requestTime"`, `routeKey` = `"$context.routeKey"`, `status` = `"$context.status"`, `responseLength` = `"$context.responseLength"`, `integrationError` = `"$context.integrationErrorMessage"` |
| `tags` | `Name` = the `project_name` variable followed by `-api-default` (the stage's own name, `$default`, would say nothing); `Role` = `"api"`; `ManagedBy` = `"terraform"` |

**Tags:** yes, through the `tags` argument above.

**Docs:** [aws_apigatewayv2_stage](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/apigatewayv2_stage) · [Access logging for HTTP APIs](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-logging.html) · [Logging variables](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-logging-variables.html) · [jsonencode](https://developer.hashicorp.com/terraform/language/functions/jsonencode)

**Without this stage, nothing works.** An API with no stage has no URL. `$default` is a special stage name: it serves at the API's base URL with no stage name in the path. `auto_deploy = true` publishes every route change straight away; without it, a route you add (including A4's) exists but never answers, and calls return `{"message":"Not Found"}`.

The `$context....` values are placeholders that API Gateway fills in for each request. Write them as ordinary strings: in Terraform, only `${` starts an expression, so `$context` is left alone. Put `$default` in quotes as a plain string for the same reason.

```

Step 2 should now be ✅. It confirms the access log group, the API, and the stage: `$default`, `auto_deploy`, access logs to the right group in JSON with all seven fields, and tags. Steps 3 and 4 stay ❌ until you build them.

## Part 3: The route (`modules/upload_api/api.tf`, continued)

A4's brief uses the same three-block pattern for the status route it adds after you. The difference: you reference your own API's `id` and `execution_arn`, where A4 receives them as variables.

#### 5. Connect the API to Lambda 1

**Block Type:** `resource`
**Resource Type:** `aws_apigatewayv2_integration`
**Resource Name:** `upload_url`

| Argument | Set To |
|---|---|
| `api_id` | the `id` of `aws_apigatewayv2_api.this` |
| `integration_type` | `"AWS_PROXY"` |
| `integration_uri` | the `invoke_arn` of `aws_lambda_function.upload_url` (not its `arn`) |
| `payload_format_version` | `"2.0"` |

**Tags:** not supported by this resource type.

**Docs:** [aws_apigatewayv2_integration](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/apigatewayv2_integration)

`AWS_PROXY` passes the whole request to Lambda 1 and returns whatever it sends back. Format `2.0` is the event shape B1's handler reads: the JSON body as a string in `event["body"]`.

#### 6. The route

**Block Type:** `resource`
**Resource Type:** `aws_apigatewayv2_route`
**Resource Name:** `upload_url`

| Argument | Set To |
|---|---|
| `api_id` | the `id` of `aws_apigatewayv2_api.this` |
| `route_key` | `"POST /upload-url"` |
| `target` | `integrations/` followed by the `id` of `aws_apigatewayv2_integration.upload_url` |

**Tags:** not supported by this resource type.

**Docs:** [aws_apigatewayv2_route](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/apigatewayv2_route)

#### 7. Let the API call Lambda 1

**Block Type:** `resource`
**Resource Type:** `aws_lambda_permission`
**Resource Name:** `api`

| Argument | Set To |
|---|---|
| `statement_id` | `"AllowApiGatewayInvoke"` |
| `action` | `"lambda:InvokeFunction"` |
| `function_name` | the `function_name` of `aws_lambda_function.upload_url` |
| `principal` | `"apigateway.amazonaws.com"` |
| `source_arn` | the `execution_arn` of `aws_apigatewayv2_api.this` followed by `/*/*` |

**Tags:** not supported by this resource type.

**Docs:** [aws_lambda_permission](https://registry.terraform.io/providers/hashicorp/aws/6.69.1/docs/resources/lambda_permission)

Without this, every call returns `{"message":"Internal Server Error"}` and the access log shows a permission error, even though the route exists. `source_arn` limits the permission to this one API; `/*/*` covers every stage and route on it.

## Done when (in your own AWS account)

These commands need the AWS CLI v2: `aws --version` should start with `aws-cli/2.`. Version 1 has no `aws logs tail` and no `--cli-binary-format`. The checks also read JSON with `jq`. If `jq --version` fails, install it first ([download jq](https://jqlang.org/download/)).

From the repo root:

```bash
terraform init -backend-config=backend.hcl
terraform apply
API=$(terraform output -raw api_url); API=${API%/}
BUCKET=$(terraform output -raw incoming_bucket_name)
FN=$(terraform output -raw upload_function_name)
MAX_MB=25        # your max_size_mb, if you changed it in terraform.tfvars
T=$(mktemp -d)   # test files go here, not in the repo

# 1. Ask for an upload URL: expect JSON with upload_id, url, and fields
RESP=$(curl -s -X POST "$API/upload-url" -H "Content-Type: application/json" \
  -d '{"filename": "cat.png", "content_type": "image/png", "size": 1024}')
echo "$RESP"
ID=$(echo "$RESP" | jq -r .upload_id)

# 2. Upload a small file with it: expect 204
head -c 1024 /dev/urandom > "$T/cat.png"
FORM=(); while IFS= read -r f; do FORM+=(-F "$f"); done < <(echo "$RESP" | jq -r '.fields | to_entries[] | "\(.key)=\(.value)"')
curl -s -o /dev/null -w "%{http_code}\n" "${FORM[@]}" -F "file=@$T/cat.png" "$(echo "$RESP" | jq -r .url)"

# 3. It landed at the expected key: expect uploads/<the same upload_id>/cat.png
aws s3 ls "s3://$BUCKET/uploads/$ID/"

# 3b. The same form can't write anywhere else: change only the key, expect 403 and "Invalid according to Policy"
FORM2=(); for f in "${FORM[@]}"; do case "$f" in key=*) FORM2+=("key=uploads/$ID/other.png") ;; *) FORM2+=("$f") ;; esac; done
curl -s -w "\n%{http_code}\n" "${FORM2[@]}" -F "file=@$T/cat.png" "$(echo "$RESP" | jq -r .url)"

# 4. A file 1 MB over the limit, with a fresh URL: expect EntityTooLarge and 400
RESP=$(curl -s -X POST "$API/upload-url" -H "Content-Type: application/json" \
  -d '{"filename": "big.png", "content_type": "image/png", "size": 1024}')
head -c $(( (MAX_MB + 1) * 1024 * 1024 )) /dev/zero > "$T/big.png"
FORM=(); while IFS= read -r f; do FORM+=(-F "$f"); done < <(echo "$RESP" | jq -r '.fields | to_entries[] | "\(.key)=\(.value)"')
curl -s -w "\n%{http_code}\n" "${FORM[@]}" -F "file=@$T/big.png" "$(echo "$RESP" | jq -r .url)"

# 5. The access log: expect JSON lines with "routeKey":"POST /upload-url"
aws logs tail "/aws/apigateway/${FN%-upload-url}-api" --since 10m

# Incoming is versioned and now holds your test file: remove every version and delete marker, or destroy fails
aws s3api delete-objects --bucket "$BUCKET" --delete "$(aws s3api list-object-versions --bucket "$BUCKET" \
  --query '{Objects: [Versions, DeleteMarkers][][].{Key: Key, VersionId: VersionId}}' --output json)"

rm -r "$T"
terraform destroy
```

Expected: (1) a JSON object with `upload_id`, `url`, `fields`, and `"expires_in": 900`; (2) `204`; (3) one line ending in `cat.png`; (3b) an XML error saying `Invalid according to Policy`, then `403`, which proves a form only works for its own key; (4) an XML error containing `<Code>EntityTooLarge</Code>`, then `400`; (5) one JSON line per request.

Things that commonly go wrong:

- **`{"message":"Not Found"}`** on step 1: the URL has a double slash (did `${API%/}` run?), the route key isn't exactly `POST /upload-url`, or the stage lacks `auto_deploy = true`.
- **`{"message":"Internal Server Error"}`**: usually the Lambda permission (section 7). Step 5's log line shows the `integrationError`.
- **`403` with `AccessDenied` on the upload**: the role's `SignUploads` statement doesn't cover `uploads/*` in this bucket (B1, section 5).
- **`403` with `Invalid according to Policy`**: a form field was changed or dropped. Send every field exactly as returned, and put `file` last (S3 ignores anything after the file), which is why it's the final `-F` in the command.
- **Any other `403`** (for example `InvalidAccessKeyId`): a field from `fields` was dropped, usually `x-amz-security-token`. The form is signed with the function's temporary credentials, and that token is part of the signature.

## After the merge

Merge the pull request on GitHub, then clean up the branch:

```bash
git switch main && git pull
git branch -D b2-api
git fetch --prune
```

`-D` rather than `-d` because this repo is squash-only: the branch's commits are never in `main` as themselves, so `git branch -d` refuses. The remote branch is already gone — `delete_branch_on_merge` removes it at merge — so `git fetch --prune` only clears the stale `origin/b2-api` ref.
