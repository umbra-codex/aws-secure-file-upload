# M0: Create the GitHub repo

| | |
|---|---|
| **Who** | The lead (Umbra), once, before anyone else starts |
| **Starting point** | The scaffold in `~/Projects/aws-secure-file-upload/` (not yet a git repo) |
| **Repo managed by** | `~/Projects/github-iac/` (Terraform/OpenTofu, `integrations/github` provider) |
| **Result** | A public repo cloned at `~/Projects/aws-secure-file-upload/`, a green first check, `main` protected, teammates added |

## Goal

Create the repo the same way as every other repo you own, as code in `github-iac`, then clone it into `~/Projects` and fill it with the scaffold. When you're done, GitHub enforces the team's rules:

- Nobody can push straight to `main`; every change arrives as a pull request.
- A pull request can't merge until the **ci** check passes and a teammate approves it.
- Changes to the check itself (`tests/`, `scripts/`, `milestones.txt`, `.github/`) need your approval, through CODEOWNERS.

## What you need installed

| Tool | Check it works |

| Git | `git --version` |
| GitHub CLI (`gh`), signed in | `gh auth status` says you're logged in as `umbra-codex` |

## Step 1: Add the repo to github-iac

Add this block to `~/Projects/github-iac/repos.tf`:

```hcl
resource "github_repository" "aws-secure-file-upload" {
  name        = "aws-secure-file-upload"
  description = "Serverless file upload pipeline with GuardDuty malware scanning, built in Terraform by a team of four"
  visibility  = "public"

  auto_init              = true
  has_issues             = true
  delete_branch_on_merge = true
  archive_on_destroy     = true

  allow_squash_merge = true
  allow_merge_commit = false
  allow_rebase_merge = false

  topics = ["aws", "terraform", "serverless", "s3", "lambda", "guardduty", "eventbridge", "dynamodb"]

  security_and_analysis {
    secret_scanning {
      status = "enabled"
    }
    secret_scanning_push_protection {
      status = "enabled"
    }
  }
}
```

`auto_init = true` creates `main` with a first commit, so the repo can be cloned and protected. Squash-only merging turns each milestone PR into one commit on `main`. Secret scanning blocks pushes that contain keys, which matters on a public repo.

```bash
cd ~/Projects/github-iac
tofu plan -out new-repo.tfplan
tofu apply new-repo.tfplan
git add repos.tf && git commit -m "feat: add aws-secure-file-upload repo" && git push
```

> **✅ Checkpoint**
> The plan shows exactly **1 to add** and nothing to change or destroy. After the apply, `gh repo view umbra-codex/aws-secure-file-upload` shows the repo.

## Step 2: Clone it and move the scaffold in

The scaffold already sits at the path the clone needs, so move it aside first, clone, then copy it in:

```bash
cd ~/Projects
mv aws-secure-file-upload aws-secure-file-upload-scaffold
gh repo clone umbra-codex/aws-secure-file-upload aws-secure-file-upload
cd ~/Projects/aws-secure-file-upload
(cd ~/Projects/aws-secure-file-upload-scaffold && tar --exclude=.terraform.lock.hcl -cf - .) | tar xf -
git status --short
```

The copy brings the Terraform scaffold, the CI check, and the team's documentation: `docs/overview.md` (the project overview), `docs/portions/` (one doc per portion), and `docs/milestones/` (every brief written so far). It brings everything except the lock file: OpenTofu wrote it for OpenTofu's registry, and the team runs Terraform. The first teammate who runs `terraform init` commits the real one. The `.terraform/` folder comes along too, so you don't download the AWS provider again; `.gitignore` keeps it out of git.

> **✅ Checkpoint**
> `git status --short` lists the scaffold's files (and `README.md` as modified), including `docs/overview.md`, the four files in `docs/portions/`, and `docs/milestones/` (M0, A1 to A4). It lists no `.terraform/`, no `*.tfstate`, no `terraform.tfvars`, no `backend.hcl`, and no `.terraform.lock.hcl`. If any of those appear, stop and check `.gitignore`.

Then commit, push, and remove the old copy once the two match:

```bash
git add -A && git commit -m "M0: repo foundation" && git push
diff -rq --exclude=.git --exclude=.terraform.lock.hcl ~/Projects/aws-secure-file-upload-scaffold . && rm -rf ~/Projects/aws-secure-file-upload-scaffold
```

`diff` prints nothing when every file matches; only then does `rm` run.

## Step 4: Protect `main` and add your teammates (github-iac)

Add these to `~/Projects/github-iac/repos.tf`, putting your teammates' GitHub usernames in the list:

```hcl
resource "github_branch_protection" "aws-secure-file-upload-main" {
  repository_id  = github_repository.aws-secure-file-upload.node_id
  pattern        = "main"
  enforce_admins = false

  required_status_checks {
    strict   = true
    contexts = ["check"]
  }

  required_pull_request_reviews {
    required_approving_review_count = 1
    require_code_owner_reviews      = true
    dismiss_stale_reviews           = true
  }
}

resource "github_repository_collaborator" "aws-secure-file-upload" {
  for_each   = toset(["TEAMMATE_1", "TEAMMATE_2", "TEAMMATE_3"])
  repository = github_repository.aws-secure-file-upload.name
  username   = each.value
  permission = "push"
}
```

```bash
cd ~/Projects/github-iac
tofu plan -out new-repo.tfplan
tofu apply new-repo.tfplan
git add repos.tf && git commit -m "feat: protect aws-secure-file-upload main and add collaborators" && git push
```

What each part means:

- `"check"` is the job name in `.github/workflows/ci.yml`; it's the check that must pass.
- `enforce_admins = false` on purpose: you're the only code owner, and GitHub never lets an author approve their own PR. When you change `tests/` or `.github/`, you merge with your admin override, and that's the only time to use it.
- `push` permission lets teammates create branches and open PRs; protection still keeps them off `main`. Each teammate gets an email invitation and must accept it.

> **✅ Checkpoint**
> The plan adds 1 branch protection plus one collaborator per teammate. On GitHub, **Settings**, then **Branches** shows the `main` rule with "Require a pull request", "Require status checks" (listing `check`), and "Require review from Code Owners".

## Step 5: Prove the protection works

```bash
cd ~/Projects/aws-secure-file-upload
git checkout -b m0-protection-test
git commit --allow-empty -m "test: branch protection"
git push -u origin m0-protection-test
gh pr create --fill
```

> **✅ Checkpoint**
> The PR shows the **check** running, then ✅, and the merge button says a review is required. Close it without merging (`gh pr close --delete-branch`), then `git checkout main`.
